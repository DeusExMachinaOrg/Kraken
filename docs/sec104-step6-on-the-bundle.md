
## §104. Шаг 6 перемерян на включённом пакете: хуже, и версия §99 опровергнута

§99 объяснил провал шага 6 тем, что колесо загоняет в упор, пока тень ненагружена в воздухе, и
записал ожидание: включённый пакет (§103) уполовинил хвостовой развал, значит остаток должен
измениться. Он изменился — в другую сторону.

### 104.1. Замер

Чередование в одной сессии, пакет включён на обоих плечах, рулевой сценарий (`WM_STEER=1.0`),
3 повтора:

| | steer=0 | steer=1 |
|---|---|---|
| ratio | 1.00 sd 0.01 | 0.95 sd 0.03 |
| pos-div (газ), м | 2.21 sd 0.15 | **7.53 sd 0.45** |
| angle (газ), ° | 9.53 sd 2.00 | **18.23 sd 0.31** |
| хвост, pos | 45.26 sd 1.67 | 45.04 sd 21.30 |
| хвост, max angle | 94.07 sd 36.33 | 69.53 sd 28.74 |
| \|err\| средняя, ° | — | 16.97 sd 2.62 |
| кадров в пределах 1° | — | 38.9 % sd 19.3 |
| насыщение sat≥0.99 | — | 32.2 % sd 1.9 |

Позиционная дивергенция втрое, угловая вдвое. Умолчание `wm4_steer` остаётся 0.

### 104.2. Почему версия §99 неверна

Она предсказывала улучшение: меньше полётов — меньше ненагруженных колёс — меньше выбиваний в упор.
Пакет полёты уполовинил, а шаг 6 стал хуже.

Причина видна в §68.2. Момент, который стоп подаёт, удерживая колесо в упоре:

```
без пакета (§99):   limRot.z = −212 … −533 Нм
с пакетом (здесь):  limRot.z до −8591 Нм,  например  0/2110/−8591  при atStop=1
```

Это ровно обратная связь, которую §99 не рассмотрел: прижимная сила поднимает нормальную нагрузку
(до 64 % веса сверх собственного), нагрузка поднимает момент в пятне контакта, а рулевая ось у нас
проходит через центр колеса — нулевой плечевой радиус, нулевой вылет, — поэтому весь этот момент
идёт прямо на шкворень. Пакет не разгрузил колесо, а **нагрузил** его сильнее.

Ограничитель мотора (4·m·g·R, здесь 4767 Нм) при 8591 Нм возмущения обязан проигрывать. Поднимать
его дальше бессмысленно: это гонка, в которой возмущение растёт вместе с нагрузкой.

### 104.3. Переформулировка задачи

Самое полезное из этого прогона — не средние, а вот это:

```
commanded=0.000 в 34 кадрах из 38
```

и при этом `measured=−0.785`, `steerTq=−4767Nm`, `sat=1.00`. То есть **колёса выбивает в упор ±45°
тогда, когда водитель вообще не поворачивает**.

Значит задача шага 6 не «следовать за командой руля» — со слежением всё в порядке, §100 показал
0.06° в спокойных кадрах. Задача — **удержать колесо прямо**. Это вопрос жёсткости и геометрии, а не
подкрутки ограничителя, и следующий ход должен быть про топологию: у настоящей машины колесо держит
рейка с большим передаточным и кингпин с ненулевым плечом, у нас — один мотор с конечным моментом.

### 104.4. Побочно: доворачивающий момент §94 по-прежнему не проверен

`yawTorque` за весь прогон: 34 кадра 0 или −0, и два по 4-5 Нм. При настоящем упоре арифметика даёт
порядок 55 Нм. Причина та же, что и у `commanded=0.000`: окно поворота в сценарии короткое, а
логирование редкое, так что момент почти не попадает в выборку.

Это надо сказать прямо: **ассист доворота портирован и ни разу не измерен**. Ни одно из чисел §101
и §103 о нём ничего не говорит — там мерился прижим. Для него нужен сценарий с длинным удержанием
руля, и он остаётся открытым пунктом, а не «проверено вместе с пакетом».
