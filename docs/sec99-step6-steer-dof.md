
## §99. Шаг 6 (руль как DOF тела): знак выведен верно, слежение работает, ворота не взяты

Шаг реализован целиком: `RotationZ` становится ограниченной осью качания с Position-мотором для
колёс, помеченных прототипом рулевыми, остальные — `MakeFixedAxis` (ноль строк солвера). Но
приёмочная проверка плана **не пройдена**, и по умолчанию рычаг выключен. Утраченная сборка эту
планку тоже не брала.

### 99.1. Что подтвердилось

**Знак выведен, а не вписан.** `steerSign = sign(Dot(X×Y, kingpin))` даёт **−1** на всех колёсах —
ровно то, что предсказывал восстановленный SPEC: рамка X = ось, Y = вперёд, значит Z = X×Y = −Y_c,
то есть Z констрейнта смотрит ВНИЗ и антипараллельна шкворню. SPEC называет это самой вероятной
тихой инверсией во всём кластере: жёстко вписанный +1 дал бы машину, которая рулит не в ту сторону
на любой скорости и всё равно проходит любую проверку по `|angle|`.

**Нерулёные колёса не тронуты.** Их `cap` печатается как `3.4e+38` (FLT_MAX) — мотор не
настраивался ни разу. Именно поэтому строка §68 эмитится и для них: подавить её для `steerable=0`
значило бы убрать эту проверку.

**Мотор следит точно, когда ему не мешают:** `cmd=-0.194 meas=-0.196 err=-0.10 deg sat=0.01`.
Кинематика, знак и обратное чтение угла верны.

### 99.2. Чего не хватает, и почему это не подкрутка

Колёса разъезжаются в упоры ±0.611 рад при команде 0.03. Диагностика §68.2 различила причину:

```
docs §68.2: steer budget w=0 limRot=0/115/-498 Nm atStop=1
docs §68.2: steer budget w=1 limRot=0/-283/-495 Nm atStop=1
docs §68.2: steer budget w=2 limRot=0/27/-1 Nm   atStop=0    (нерулёное, для контраста)
```

`limRot.x = 0` всегда — ось спина действительно свободна (заодно проверка шага 5). А в упоре
механический стоп подаёт **212–533 Нм**: колесо туда реально загоняет внешний момент.

Момент физичен, а не баг. Рулевая ось проходит через центр колеса — нулевой плечевой радиус и
нулевой вылет, — поэтому любое смещение пятна контакта от вертикали даёт `R·F` вокруг шкворня:
0.635 м × 800 Н = 508 Нм, ровно наблюдаемый диапазон. У настоящей рейки жёсткость на порядок выше;
руль водителя не выбивает в упор кочкой.

**Общий с ручником ограничитель — не тот рычаг.** Доказательством общности была ОДНА совпавшая пара
в восстановленном логе (`cap=3020` и `cmdTq=3020` на колёсах 0/1 в одном кадре), причём более
сильное утверждение, построенное на ней, верификация опровергла. Ограничитель получил собственное
значение `4·m·g·R` (≈1730 Нм для Molokovoz01, восьмикратный запас над измеренными 533 Нм),
конечное — бордюр обязан в итоге побеждать, чего FLT_MAX не позволил бы.

Это помогло, но не закрыло:

| | общий ограничитель | собственный |
|---|---|---|
| насыщение `sat≥0.99` | 33–39 % кадров | 11–17 % |
| `sat` среднее | 0.39 | 0.16 |
| прямая, ratio | 0.85 | 0.92 |
| руль в упор, pos-div | 20.9 м | 5.46 м |

### 99.3. Почему по умолчанию 0

Включение шага 6 сдвигает проверенный бейслайн шага 5:

```
wm4_steer=0 : ratio 1.00 sd 0.01   pos-div 2.52 sd 0.23   (3 повтора)
wm4_steer=1 : ratio 0.92           pos-div 24.80
```

Прогон с выключенным рычагом сделан **специально как контроль**: он доказывает, что просадку даёт
именно включение шага 6, а не какая-то другая правка этого коммита (вывод знака, строки §68,
перестройка охранников). Рычаг действительно откатывает.

Ставить шаг по умолчанию включённым, когда он измеримо ухудшает последний проверенный, значило бы
спрятать регресс за галочкой «сделано». Утраченная сборка отгружала 1 — это сознательное
расхождение, а не совпадение.

### 99.4. Главный подозреваемый — выдуманная константа

`kApproxMaxSteerAngleRadians` = 35° **не игровые данные**. Файл говорит это прямым текстом в месте
объявления: у `hta::ai::Wheel::STEERING_LIMIT` нет восстановленного значения, а §94.2 показывает,
что реальные упоры ODE на рулевой оси — 0 для нерулёных колёс и ±π для рулевых. **У эталона нет
ограничения в 35° вообще.**

То есть колесо упирается в стоп, которого в эталоне не существует, и упирается настолько, что стоп
подаёт полкиловатт-метра реакции. Это не значение для подкрутки, а решение о модели, и следующий шаг
здесь — не поднимать ограничитель ещё раз, а решить вопрос про сам упор: взять настоящее значение из
игровых данных либо явно признать его свипируемой константой и прогнать свип.

### 99.5. Что осталось непроверенным

- Ворота «руль в бордюр не заклинивает и не продавливает» — нужен сценарий с препятствием.
- Ворота «ручник держит на уклоне» из шага 5 — по-прежнему нужен сценарий с уклоном.
- Хвост торможения (159°) — по-прежнему §94, а не шаг 6; см. §98.4.
