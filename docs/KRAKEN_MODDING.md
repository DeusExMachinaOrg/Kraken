# Kraken — мануал для мододелов

Kraken — это DLL-инжектор для *Hard Truck Apocalypse* (Ex Machina).
Он чинит баги движка, добавляет фичи и выносит часть игровых констант в конфиг.
Этот документ описывает **все параметры конфига**, **новую модель столкновений (таран/шипы)**
и **какие значения задаются в `kraken.ini`, а какие — в игровых XML**.

---

## 1. Где что лежит

| Что | Путь |
|-----|------|
| Конфиг Kraken | `data/kraken.ini` (рядом с игрой) |
| Лог Kraken | `kraken.log` (в папке игры; перезаписывается при каждом старте) |
| XML машин | `data/gamedata/.../vehicles*.xml` |
| XML шипов/оружия | `data/.../specialguns.xml` и пр. |

`kraken.ini` **создаётся и до-заполняется автоматически**: при старте Kraken читает все
ключи, применяет дефолты для отсутствующих и записывает файл обратно. Поэтому удобно
запустить игру один раз, закрыть — и редактировать уже сгенерированный файл с полным набором ключей.

> ⚠️ Все числа с плавающей точкой пишутся в формате `1.250000`. Целочисленные флаги — `0`/`1`.
> Значения вне допустимого диапазона **обрезаются** до min/max (см. таблицы ниже).

## 2. Параметры конфига `kraken.ini`

### [logging]
| Ключ | Тип | Дефолт | Диапазон | Описание |
|------|-----|--------|----------|----------|
| `log_debug` | uint | 1 | 0..5 | **Порог** уровня логирования. Пишутся сообщения с уровнем `>=` этого значения. `0` = debug (всё), `1` = info, `2` = warning, `3` = error, `4` = panic, `5` = ничего. Для отладки моделей ставь `0`. |

### [graphics]
| Ключ | Тип | Дефолт | Диапазон | Описание |
|------|-----|--------|----------|----------|
| `save_width`  | uint | 512  | 256..2048 | Ширина картинки-превью, которую игра рендерит и сохраняет вместе с сейвом. Больше — чётче превью сейва, но сейв тяжелее. |
| `save_height` | uint | 256  | 128..1024 | Высота того же превью сейва. |
| `view_resolution` | uint | 2048 | 128..4096 | Разрешение текстуры, в которую рендерится «осмотр» объекта (превью машины/товара при наведении/в гараже). Больше — чётче модель в окне осмотра, дороже по видеопамяти. |

### [constants]

Многие ключи здесь — это либо **подмена «зашитой» в .exe константы** на значение из
ini, либо **тумблер фикса** (`0`/`1`). Подробно по каждому:

**`gravity`** — float, дефолт `-9.81`, диапазон `-100..0`.
Глобальная гравитация физики (ODE). Чем меньше (отрицательнее), тем сильнее всё
прижимает к земле и тем «тяжелее» прыжки/подвеска. Прямо переписывает константу движка.

**`price_fuel`** — uint, дефолт `50`, диапазон `1..10000`.
Базовая цена единицы топлива в торговле/заправке. Подменяет зашитую константу цены.

**`price_paint`** — uint, дефолт `50`, диапазон `1..10000`.
⚠️ **Сейчас НЕ работает** — соответствующий патч цены покраски отключён в коде
(`ConstantHotfix`), движок берёт свою цену. Ключ остаётся как задел, менять его смысла нет.

**`keep_throttle`** — float, дефолт `1.0`, диапазон `0..1`.
Доля удерживаемого газа (инерция педали газа). `1.0` = ванильное поведение. Меньше —
газ быстрее «отпускается», машина резче замедляется при снятии газа.

**`handbrake_power`** — float, дефолт `1.0`, диапазон `0..1`.
Сила ручного тормоза (`1.0` = ваниль/полная). Меньше — ручник держит слабее.

**`brake_power`** — float, дефолт `-1.0`, диапазон `-1..0`.
Сила рабочего тормоза (значение отрицательное по соглашению движка; `-1.0` = полная).
Ближе к `0` — тормоза слабее.

**`friend_damage`** — uint (0/1), дефолт `0`.
`0` — союзники (один тим) **не** получают урон друг от друга (правит зашитый флаг
дружественного огня). `1` — дружественный урон включён, как в ванили.

**`auto_brake_angle`** — uint (градусы), дефолт `50`, диапазон `0..180`.
Порог для **ИИ-водителей**: если угол поворота к следующей точке маршрута больше этого
значения, ИИ автоматически притормаживает перед поворотом. Меньше угол → ИИ осторожнее
(тормозит даже на пологих поворотах); больше → почти не тормозит и чаще срывается с трассы.
На управление игроком не влияет.

**`posteffectreload`** — uint (0/1), дефолт `0`.
`1` — при смене погоды/времени суток Kraken **перечитывает погодный XML** заново
(горячая перезагрузка пост-эффектов). Полезно при правке погодных конфигов — изменения
видны без перезапуска уровня. `0` — выключено (обычный режим).

**`ultrawide`** — uint (0/1), дефолт `0`.
`1` — фикс соотношения сторон для ultrawide-мониторов (правит зашитый коэффициент
aspect ratio, чтобы картинка не была растянутой на сверхшироких разрешениях). `0` — ваниль.

**`obj_cont_upgrade`** — uint (0/1), дефолт `1`.
`1` — **увеличивает лимит объектов в контейнере мира** с 16384 (`0x4000`) до 32768
(`0x8000`). Нужно для больших/плотных карт: без этого на перегруженных локациях объекты
не помещаются и игра может падать/терять объекты. Эту опцию можно включать на существующих сейвах.
Однако сейвы, которые были сохранены с obj_cont_upgrade `1`, не будут работать с obj_cont_upgrade `0` (будет вылет).
`0` — ванильный лимит.

**`show_load_every`** — uint, дефолт `100`, диапазон `0..UINT_MAX`.
Как часто перерисовывать экран загрузки: кадр загрузки рендерится **раз в N
загруженных объектов** (ваниль = 1, т.е. каждый объект). Больше значение → реже
перерисовка → **быстрее загрузка** уровня (полоска просто обновляется реже). `100` —
заметно ускоряет загрузку без видимых минусов.

**`cardan_fix`** — uint (0/1), дефолт `1`.
`1` — чинит **анимацию кардана/трансмиссии шасси**: в ванили анимация привода могла
дёргаться/не останавливаться корректно на стопе и на движущихся поверхностях (учёт
скорости поверхности под колёсами). `0` — ванильное поведение анимации.
(Сам хук газа ставится всегда; флаг включает только корректировку анимации шасси.)

**`wares`** — uint (0/1), дефолт `0`.
`1` — включает **кастомный ремонт/дозаправку расходниками**: по **Ctrl+клику** на товаре
в инвентаре машина чинится или заправляется на величины, заданные в секциях
`[REPAIR_N]`/`[REFUEL_N]` (см. ниже). `0` — фича выключена.

**`cctl_leak_fix`** — uint (0/1), дефолт `1`.
`1` — чинит **утечку/порчу памяти в системе контактов столкновений** (буфер
`LocalContacts` в `dCollideCCTL`): в ванили буфер контактов выделялся неправильно, что
приводило к утечкам и потенциальным вылетам при интенсивных столкновениях. Рекомендуется
держать `1`. `0` — ванильное (багованное) поведение.

**`mortarvolleylauncherfix`** — uint (0/1), дефолт `1`.
`1` — чинит **залповый миномёт**: заставляет его выпускать **весь залп разом** (все стволы
из `fireLpMatrices` за один раз, в пределах боезапаса), а не по одному снаряду с
неправильной перезарядкой. `0` — ванильное (сломанное) поведение залпа.

**`gunlights`** — uint (0/1), дефолт `1`.
`1` — включает **фары/подсветку на орудиях и турелях**: даёт оружейным установкам
работающий «фонарь» (фары на стволе/турели зажигаются вместе с фарами машины и ночью у
стационарных турелей). `0` — без подсветки орудий.

**`appendix`** — uint (0/1), дефолт `1`. **Главный тумблер шипов.**
`1` — включает логику Appendix (шипы как навесное оружие) **и новую модель столкновений**
(см. §3). `0` — всё это выключается: тараны считаются **ванильным** движком, хуки шипов не
ставятся. (Сам класс Appendix остаётся зарегистрирован, чтобы старые сейвы/прототипы с
шипами грузились без вылета — просто без новой логики урона.)

| `lock_on_player` | uint (0/1) | 1 | Враги «фиксируются» на игроке как на цели (не перескакивают на случайные цели, пока игрок в зоне атаки). `0` — выбор цели как в ванили. |

### [glob_phys] — глобальная физика ODE
Это параметры солвера движка ODE. **Трогать осторожно** — влияют на всю физику разом.
| Ключ | Тип | Дефолт | Диапазон | Описание |
|------|-----|--------|----------|----------|
| `contact_surface_layer` | float | 0.01 | 0..1 | Толщина «мягкого» проникающего слоя в контактах. Больше — объекты слегка «проваливаются» друг в друга без дрожания; 0 — жёсткие контакты (могут дрожать). |
| `cfm` | float | 0.0001 | 0..1 | Constraint Force Mixing — «мягкость» связей солвера. Больше → связи податливее/стабильнее, но физика «резиновее». |
| `erp` | float | 0.1 | 0..1 | Error Reduction Parameter — как быстро солвер исправляет проникновения/ошибки связей за шаг. Больше → жёстче возврат, но менее стабильно. |

### [schwarz] — расчёт цен (теневая стоимость / «шварц»)
Система пересчёта рыночной стоимости машины и навесного с учётом установленных гаджетов и
модификаций. По умолчанию выключена (`complex_schwarz=false`) — работает ванильное
ценообразование.
| Ключ | Тип | Дефолт | Описание |
|------|-----|--------|----------|
| `complex_schwarz` | bool | false | Главный тумблер сложного расчёта стоимости. `false` — ваниль. |
| `calc_peace_price_from_schwarz` | bool | false | Считать «мирную» цену объекта из его теневой стоимости. |
| `no_money_in_player_schwarz` | bool | false | Не учитывать наличные деньги в теневой стоимости имущества игрока. |
| `gun_gadgets_max_schwarz_part` | float | 0.0 (0..10) | Максимальная доля, которую боевые гаджеты могут добавить к стоимости. `0` — без вклада. |
| `common_gadgets_max_schwarz_part` | float | 0.0 (0..10) | То же для обычных (небоевых) гаджетов. |
| `wares_max_schwarz_part` | float | 0.0 (0..10) | То же для товаров/расходников. |

`[schwarz_overrides]` — секция произвольных пар `имя_прототипа=число`: жёстко задаёт
теневую стоимость для конкретных прототипов (точечное переопределение).

### [REPAIR_N] / [REFUEL_N] — расходники ремонта/заправки (нужен `constants:wares=1`)
Описывают, **что произойдёт по Ctrl+клику** на конкретном товаре в инвентаре. `N` —
номер с 1 (`[REPAIR_1]`, `[REPAIR_2]`, …), читаются до первого пропуска. Ремонт «умный»:
HP чинится в первую очередь, затем броня распределяется по самым повреждённым деталям.
| Ключ | Где | Описание |
|------|-----|----------|
| `Units` | REPAIR/REFUEL | Сколько восстановить: HP (REPAIR) или топлива (REFUEL) за одно применение. `0` — ничего не восстанавливать (вся логика — в `Script`). |
| `Armor` | только REPAIR | Сколько брони/прочности деталей дополнительно восстановить. |
| `Ware` | REPAIR/REFUEL | Имя прототипа товара-расходника, на котором срабатывает Ctrl+клик (напр. `scrap_metal`, `fuel`). |
| `Sound` | REPAIR/REFUEL | Звук при применении (`SOUND_REPAIR` / `SOUND_REFUEL`). |
| `Script` | REPAIR/REFUEL | Необязательно. Имя Lua-скрипта, который выполнится при применении (через `ScriptServer::execute(..., "Kraken")`). Скрипт может делать что угодно. Если `Units=0`/`Armor=0`, вся логика остаётся за скриптом. |
| `Consume` | REPAIR/REFUEL | Необязательно (дефолт `1`). `1` — товар тратится при применении (как раньше); `0` — товар остаётся в инвентаре (многоразовое применение). |

> Применение «срабатывает» (товар обрабатывается нами, ванильный клик подавляется),
> если что-то реально восстановилось **или** задан `Script`. Так можно сделать чисто
> скриптовый предмет (`Units=0`, `Armor=0`, `Script=...`), логика которого не связана
> с ремонтом/заправкой. `Script` выполняется до списания товара, поэтому скрипт ещё
> видит предмет в инвентаре.

## 3. Модель столкновений (таран + шипы)

> Активна только при `[constants] appendix = 1`. При `0` — ванильная физика урона.

Kraken **полностью заменяет** движковые `CalcDamageToVehicles` и
`CollideVehiclePartAndVehiclePart` своей моделью. Это гибрид: физически корректная
база по массе + множители «агрессии», направленной брони и шипов.

### 3.1 Формула

Для каждого участника столкновения (`V1` и `V2`) урон считается **независимо**:

```
v       = |проекция относительной скорости сближения на нормаль контакта|   (м/с)
vEff    = max(0, v - speed_threshold)
term    = damage_coeff * vEff ^ speed_exponent

share1  = m2 / (m1 + m2)        // доля для V1: лёгкого бьёт сильнее
share2  = m1 / (m1 + m2)        // для статики (труба/стена): share1 = 1, share2 = 0

armor_i = направленная броня цели i (см. 3.3)
offense_j = «агрессия тарана» бьющего j (см. 3.4)
thorn_j   = множитель шипов бьющего j = 1 + ThornForce_j * thorn_scale (см. 3.5)

damageToV1 = clamp( term * share1 * offense2 * thorn2 * armor1, 0, max_damage )
damageToV2 = clamp( term * share2 * offense1 * thorn1 * armor2, 0, max_damage )
```

Тип урона — `DAMAGE_BLAST`. **Сопротивление цели в формулу НЕ входит** — движок сам
умножает результат на blast-сопротивление цели в `Vehicle::InflictDamage`.
То есть «броню по типу урона» по-прежнему настраивают штатными средствами в XML машины.

Ключевые идеи:
- **Масса несёт размер.** Тяжёлая машина наносит больше (большой `share` оппоненту),
  получает меньше. Статичное препятствие = бесконечная масса (`share` к нему = 0).
- **`offense`/`thorn`/`armor` — отдельные множители**, не дублируют массу.
- **`speed_threshold`** убирает урон от парковочных тычков.
- **`max_damage`** — предохранитель от ваншотов на скачках скорости физики.

### 3.2 Параметры в `kraken.ini` → `[thorncollide]`
| Ключ | Дефолт | Диапазон | Смысл |
|------|--------|----------|-------|
| `speed_threshold` | 5.0 | 0..1000 | Порог скорости сближения; ниже — урона нет. |
| `damage_coeff` | 2.7 | 0..100000 | Главный масштаб урона (K). |
| `speed_exponent` | 1.0 | 0.1..4.0 | Степень скорости: `1.0` = импульс (линейно), `2.0` = энергия (квадратично). |
| `max_damage` | 100000 | 0..1e9 | Потолок урона за одно касание (по сути выкл при таком значении). |
| `armor_front` | 0.8 | 0.01..100 | Множитель урона при ударе в **лоб** (`<1` = крепче). |
| `armor_side` | 1.25 | 0.01..100 | …в **борт**. |
| `armor_rear` | 1.0 | 0.01..100 | …в **корму**. |
| `landscape_offense` | 0.5 | 0..100 | «Агрессия» статичных препятствий (труба, стена). |
| `thorn_scale` | 0.02 | 0..100 | Шкала шипов: множитель = `1 + ThornForce * thorn_scale`. |

Дефолты подобраны так, что скаут об трубу на средней скорости получает ~30 урона
(как в Meridian 113).

### 3.3 Направленная броня (`armor_*`)
Считается **непрерывно** по косинусу угла между направлением машины «вперёд» и
направлением на точку контакта:
```
cos >= 0 (удар спереди):  armor = lerp(armor_side, armor_front, cos)
cos <  0 (удар сзади):    armor = lerp(armor_side, armor_rear, -cos)
```
То есть точно в лоб → `armor_front`, точно в бок → `armor_side`, точно в корму → `armor_rear`,
промежуточные углы интерполируются.

### 3.4 «Агрессия тарана» offense — атрибут XML `RamOffense`
Это per-vehicle множитель силы тарана (аналог `HitForce` из Meridian 113, но масса
учитывается уже отдельно, поэтому offense не должен повторять размер машины).

- Задаётся в XML машины: `<Prototype ... RamOffense="1.5">`.
- **Дефолт `1.0`**, если атрибут не указан.
- **Наследуется по `ParentPrototype`**: если у потомка нет своего `RamOffense`, берётся
  значение родителя.
- Для статичных препятствий (ландшафт) используется `landscape_offense` из конфига.

### 3.5 Шипы (Appendix) — атрибуты XML
Шипы описываются как прототип в XML спецоружия (`specialguns.xml`). Атрибуты:

| Атрибут XML | Тип | Дефолт | Смысл |
|-------------|-----|--------|-------|
| `AppendixType` | int | 0 | Тип навески (категория шипа). |
| `ThornForce` | float | 1.0 | «Сила шипа». Множитель урона = `1 + ThornForce * thorn_scale`. Напр. при `thorn_scale=0.02`: `ThornForce=25 → ×1.5`, `75 → ×2.5`. Машина без шипа → множитель `1.0`. |
| `LoadPoint` | string | — | Точка крепления модели шипа на машине. |
| `Scale` | float | 1.0 | Масштаб модели шипа (визуальный размер). |

Без указания атрибута берётся дефолт, и об этом пишется строка в лог (см. §4).

## 4. Диагностика: лог источников параметров

При `log_debug = 0` Kraken пишет в `kraken.log`, **какие параметры взяты из XML, а где
сработал дефолт**. Это помогает поймать опечатки в атрибутах.

Примеры строк:
```
[APPENDIX]  appendix 'thorn1': ThornForce = 25.000 (from XML)
[APPENDIX]  appendix 'thorn1': Scale = 1.500 (from XML)
[APPENDIX]  appendix 'someGun': AppendixType = 0 (DEFAULT, no XML attr)

[RAMCOLLIDE] vehicle 'Tank':   RamOffense = 2.000 (from XML)
[RAMCOLLIDE] vehicle 'Scout01': RamOffense = 1.500 (inherited from ParentPrototype 'Scout', no own attr)
[RAMCOLLIDE] vehicle 'Scout':  RamOffense = 1.000 (DEFAULT, no XML attr)
```
`(from XML)` — значение прочитано из атрибута; `(inherited …)` — взято у родителя;
`(DEFAULT …)` — атрибута нет, используется дефолт.

## 5. Быстрые рецепты тюнинга

| Хочу… | Что менять |
|-------|-----------|
| Совсем убрать кастомные шипы и модель тарана | `[constants] appendix = 0` |
| Сделать тараны в целом убойнее | ↑ `damage_coeff` |
| Урон рос быстрее со скоростью | `speed_exponent = 2.0` (энергия) |
| Меньше урона на лёгких тычках | ↑ `speed_threshold` |
| Запретить ваншоты | ↓ `max_damage` (напр. 200) |
| Лоб крепче, борта уязвимее | ↓ `armor_front`, ↑ `armor_side` |
| Конкретная машина — «таран» | `RamOffense="2.0"` в её XML |
| Шип бьёт сильнее | ↑ `ThornForce` в XML шипа или ↑ `thorn_scale` глобально |
| Труба/стена калечат сильнее | ↑ `landscape_offense` |

## 6. Сводка: где задаётся параметр

| Параметр | Где |
|----------|-----|
| `speed_threshold`, `damage_coeff`, `speed_exponent`, `max_damage` | `kraken.ini [thorncollide]` (глобально) |
| `armor_front/side/rear`, `landscape_offense`, `thorn_scale` | `kraken.ini [thorncollide]` (глобально) |
| `RamOffense` | XML машины (per-vehicle, наследуется) |
| `ThornForce`, `AppendixType`, `LoadPoint`, `Scale` | XML шипа (per-thorn) |
| Сопротивление по типу урона (BLAST) | штатный XML машины (движок) |
| Включение/выключение всей системы | `kraken.ini [constants] appendix` |
