# Handoff: статус Jolt-интеграции на 2026-07-22 (после §22.9: реализация и живой тест экспорта статических препятствий)

Снимок состояния для передачи работы. Эта сессия продолжает предыдущую (§18-22.8: профилирование,
Nelder-Mead, дизассемблирование NearCallback, UAF-фикс, живая diff-диагностика, подтверждённый
пользователем баг "машина проходит сквозь камни/машины", исследование пути перечисления статики).
Читать `docs/jolt-integration-techanalysis.md` §22.6-22.10 (особенно 22.9), не эту сводку, за
деталями/кодом/цифрами.

## Что сделано в этой сессии (по порядку)

1. **Новый инструмент `tools/dual_agent.py`** (не влияет на код мода) - Investigator+Validator,
   два раунда локальной qwen3-coder друг против друга, поверх существующей инфраструктуры
   `local_agent.py`/`lora_agent.py`. Использован для первичной разведки хук-пойнта - дал
   направление (нашёл `m3d::CWorld::LoadStaticObstacles` как кандидата), но не конкретные факты;
   все финальные адреса/сигнатуры перепроверены вручную.
2. **Отвергнута гипотеза `LoadStaticObstacles`** - строит только AI-навигационные `ai::Obstacle`/
   `Obb` объекты, ни одного ODE-вызова, тот же тупиковый класс что и в §22.7.
3. **Найден и исправлен реальный баг в собственном плане §22.7**: `dSpaceGetGeom` - настоящий
   PDB-символ, но дизассемблирование его vtable-слота показало dead-стаб базового класса
   (`dxSpace::getGeom` = `xor eax,eax; ret 4`, не переопределён `dxHashSpace`). Пойман живьём
   (первая сборка залогировала "exported 0..." при ненулевом total). Рабочий путь: обход
   `dxSpace::m_firstEnabled`/`m_firstDisabled` через `dxGeom::next` (intrusive linked list,
   подтверждено `class_overview`).
4. **Реализован и собран `ExportStaticObstaclesToJolt`** (`source/fix/jolt.cpp`) - box, sphere,
   **и trimesh** (изначально не планировался - PDB этого форка раскрывает `Opcode::MeshInterface`
   с обычными читаемыми полями + рабочие `dGeomTriMeshGetTriangleCount`/`dGeomTriMeshGetTriangle`,
   вопреки предположению §22.7 об "непрозрачности"). Class-ID константы подтверждены
   дизассемблированием, не предположены.
5. **Второй живой баг найден и исправлен**: `Assert failed: Quat.inl:398 (IsNormalized())` -
   тысячи раз в логе (не фатально, но неверная физика для затронутых тел) - `dQfromR` не для
   каждого геома отдаёт единичный кватернион. Исправлено защитным `.Normalized()` + откат на
   identity при вырожденном случае.
6. **Живой тест на реальном уровне** (после обоих фиксов, чисто): `exported 2357 static
   obstacles (719 box, 38 sphere, 1600 trimesh) - 2577 geoms walked in gGlobalSpace (2577 total
   per dSpaceGetNumGeoms), 0 dynamic geoms skipped, 220 body-less geoms of unexported class
   skipped`. Ноль ассертов/ошибок после фикса, процесс стабилен. `walkedCount == numGeoms` точно.
7. **`cMaxBodies` поднят 1024→8192** (`cMaxBodyPairs`/`cMaxContactConstraints` тоже) - новый
   источник тел может добавить тысячи статических body на уровень.
8. **Деплой готов к тесту пользователем**: `kraken.ini` выставлен на `[jolt] enabled=1`,
   `[jolt_harness] apply=1 player_only=1 shadow=1` - следующий шаг ждёт живого подтверждения от
   пользователя (проехать в камень/здание).

## Текущее состояние деплоя (`F:\HTA_Kraken`)

- `hta.exe` **не запущен**.
- `kraken.dll` - актуальная сборка ветки `jolt`, включает весь §22.9 (static-obstacle export +
  оба живых фикса).
- `data/kraken.ini` - **`[jolt] enabled=1`**, **`[jolt_harness] apply=1 player_only=1 ai_count=0
  shadow=1`** - готово для живого теста тарана пользователем. Тюн-значения подвески/трения из
  прошлых сессий сохранены (`susp_frequency=1.80 susp_damping=0.60 friction_long=0.93
  friction_lat=1.00`). **Важно**: ini-парсер учитывает только первое вхождение секции - проверять
  `grep -n "^\[jolt\]"` при сомнении.
- `kraken.log` - текущий (после последнего живого теста этой сессии) содержит чистый прогон без
  ошибок; предыдущий (с ассертами до фикса) сохранён как `kraken.log.bak` для истории при желании
  сравнить - можно удалить.

## Известные, честно неполные места (не баг, осознанный scope)

1. **Capsule (58 экземпляров на тестовом уровне)** - не экспортируется. Нужен доворот локальной
   оси капсулы (Z в ODE, Y в Jolt) перед созданием `JPH::CapsuleShape` - не реализовано, чтобы не
   гадать с направлением доворота без немедленной визуальной проверки.
2. **Вложенные под-спейсы** (154 `dxSimpleSpace` + минимум 1 другой space-класс, class 11-14 по
   `dGeomIsSpace`) - не рекурсируется, размер реального пробела внутри них не измерен.
3. **"Другие машины"** - отдельная, более сложная задача (динамическое зеркалирование ODE→Jolt
   каждый кадр + архитектурное решение по нескольким Jolt-ведомым машинам одновременно). Не
   начата.
4. **Живое подтверждение самого исправления** - код проверен на "не крашит, логирует разумные
   числа", но НЕ проверено пользователем визуально, что машина реально перестала проходить сквозь
   box/sphere/trimesh-статику под `apply=1`.
