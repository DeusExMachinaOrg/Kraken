# Handoff: статус Jolt-интеграции на 2026-07-22 (после §22.14: полный проход по всем оставшимся пунктам)

Снимок состояния для передачи работы. Пользователь попросил "составь план по всему, что осталось
по jolt и реализуй, не останавливайся, пока не будут выполнены все пункты" - весь список из §22.12
выполнен в этой же сессии. Читать `docs/jolt-integration-techanalysis.md` §22.9-22.15 (самые
свежие), не эту сводку, за деталями/кодом/цифрами.

## Что сделано в этой сессии (по порядку)

1. **`ExportStaticObstaclesToJolt`** (§22.9) - box/sphere/trimesh статика в Jolt. Два реальных
   бага найдены и исправлены по дороге: `dSpaceGetGeom` dead-стаб (обход через
   `m_firstEnabled`/`m_firstDisabled`+`dxGeom::next`), не всегда единичный кватернион из
   `dGeomGetQuaternion` (`.Normalized()` защитно).
2. **Живой регресс от пользователя, исправлен** (§22.10): `apply=1`, оставленный включённым,
   заставлял Jolt вести демо-машину главного меню, которая застревала о новую статику - похоже на
   "зависание". Плюс реальный баг производительности: экспорт перезапускался 30 раз вместо
   одного. Оба исправлены; `apply` возвращён на безопасный `0` по умолчанию.
3. **"Другие машины" - kinematic-зеркалирование** (§22.11, `MirrorOtherVehicles`) по запросу
   пользователя - чужие машины получают простое box-тело в Jolt, синхронизируемое каждый кадр.
4. **Capsule-экспорт + рекурсия во вложенные под-спейсы** (§22.13) - оба честных пробела из §22.9
   закрыты. Capsule: доворот оси Z(ODE)→Y(Jolt). Под-спейсы: `WalkSpaceForStaticExport` стал
   рекурсивным, нашёл 155 вложенных `dxSimpleSpace`, оказавшихся в основном контейнерами
   динамики, не дополнительной статики.
5. **Критичный баг вместимости найден на РЕАЛЬНОМ сейве и исправлен** (§22.14): `cMaxBodies=8192`
   давало только ~25% реального экспорта на настоящем уровне (24732 ошибки "out of bodies").
   Поднято до 65536 - живой повтор дал `exported 32861 static obstacles`, 0 ошибок.
6. **Живое направленное подтверждение фикса тарана** (§22.14) - через `testharness`
   (autoload реального сейва + scripted-driving), 60-секундный прогон под `apply=1` полным
   газом: несколько чётких столкновений (резкая потеря скорости+вращение под постоянным
   throttle=1), закончился полностью остановленной машиной. До фикса машина проехала бы всю
   дистанцию без остановки. Заодно выяснилось: скриптованное вождение уже прекрасно работает под
   `apply=1` (старое опасение из прошлых сессий не воспроизвелось - фикс не понадобился).
7. **Несколько одновременных Jolt-ведомых машин проверено живьём** (§22.14) - `ai_count=4
   player_only=0`, 5 машин одновременно (игрок+4 AI), 0 ошибок, `MirrorOtherVehicles` корректно
   не дублирует зеркала для уже Jolt-ведомых машин.
8. **Wheel-tear UAF (§22.2) подтверждён живьём против ТОЧНОГО условия фикса** (§22.14) - добавлен
   debug-хук (`tear_wheel_at_t`), дизассемблирование `WheelRuntimeInfo::SetWheel` дало точный
   механизм (`m_bWheelPresent`), фикс сработал ровно как задуман: обнаружение → предупреждение →
   чистый ребилд, без крашей.

## Текущее состояние деплоя (`F:\HTA_Kraken`)

- `hta.exe` **не запущен**.
- `kraken.dll` - актуальная сборка ветки `jolt`, включает §22.9-22.14 целиком.
- `data/kraken.ini` - возвращён на БЕЗОПАСНЫЙ дефолт после всех тестов: `[jolt] enabled=1`,
  `[jolt_harness] apply=0 player_only=1 ai_count=0 shadow=1`, `[testharness] enabled=0
  autoload_save=0 god_mode=0 tear_wheel_at_t=-1` (все тестовые тумблеры выключены). **Пользователь
  должен сам включить `apply=1` ПОСЛЕ входа в свой сейв**, не сидя в главном меню (§22.10). Тюн-
  значения подвески/трения сохранены (`susp_frequency=1.80 susp_damping=0.60 friction_long=0.93
  friction_lat=1.00`). **Важно**: ini-парсер учитывает только первое вхождение секции.
- `data/kraken_testharness/scenario.csv` - переписан этой сессией (60-секундный прямой разгон,
  throttle=1) для направленного теста тарана - можно переиспользовать или перезаписать.
