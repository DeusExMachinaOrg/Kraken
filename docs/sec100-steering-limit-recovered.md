
## §100. `Wheel::STEERING_LIMIT` восстановлена: это π/4, а не выдуманные 35°

§99 назвал главным подозреваемым выдуманную константу упора руля и записал следующий ход: разбираться
с самим упором, а не поднимать ограничитель момента. Подсказка пользователя — «в функции поворота
колёс игроком зашит упор на π/4» — привела прямо к нему.

### 100.1. Что найдено и как проверено

Сканирование `hta.exe` на float32 `0x3f490fdb` даёт два выровненных вхождения; одно по rva
`0x5931f4`. По этому же адресу PDB кладёт **`ai::Wheel::STEERING_LIMIT`**:

```
find_data "*STEERING_LIMIT*" -> {'name': 'ai::Wheel::STEERING_LIMIT', 'rva': '0x5931f4', 'type': 'float'}
read_value 0x5931f4         -> hex32 0x3f490fdb, float 0.7853981852531433
```

То есть **`STEERING_LIMIT = π/4 = 45°`**, и у неё есть настоящее адресуемое хранилище.

Игроцкое управление грузит её оттуда напрямую — `CMiracle3d::Controls`, `game.cpp:305-309`:

```
0x40178c: mov   eax, [0x9931f4]      ; +STEERING_LIMIT
0x401791: push  eax
0x401794: call  ai::Vehicle::SetSteer
0x40177c: subss xmm0, [0x9931f4]     ; -STEERING_LIMIT  -> SetSteer
0x401775: push  0                    ;  0               -> SetSteer
```

Команда руля у игрока — трёхпозиционная: ±45° либо ноль, ничего между. Это клавиатурный ввод.

### 100.2. Что этим снято

Комментарий в `joltshadow.cpp` утверждал, что у `STEERING_LIMIT` «нет определения нигде в
extern/hta… вероятно свёрнута в непосредственные операнды без адресуемого хранилища, поэтому
значение не восстановлено», и подставлял «правдоподобный общий максимум» 35°. Восстановленный SPEC
повторял это как незакрытую неизвестную. **Оба утверждения неверны**: хранилище есть, значение
известно, и оно на 28.6 % больше подставленного.

Это была не безобидная аппроксимация. Игра командует ровно ±STEERING_LIMIT, а я зажимал и команду,
и механический упор в 35°, — значит **любая реальная команда руля лежала за моим упором, и колесо
садилось на стоп по построению**. Ровно тот механизм, который §99 искал.

### 100.3. Вторая поправка из той же функции

`ai::Vehicle::_KeepSteer` (RVA 0x1da940, `vehicle.cpp:5225-5309`) считает цель каждого колеса как

```
cvtsi2ss xmm1, dword ptr [esi + 0x14c]   ; (int)wheel->m_steering
mulss    xmm1, dword ptr [edi + 0x260]   ; * vehicle->m_steerRadians
```

и затем рейт-лимитирует `m_curAngle` (`Wheel+0x15c`) к ней со скоростью `m_steeringSpeed`, вызывая
`_TurnWheelByAngle` с **разностью**.

Отсюда два вывода. Первый: `m_steering` — знаковый **множитель**, а не флаг (`STEERING_NO=0`,
`STEERING_CORRECT`, `STEERING_INVERSE`), то есть направление поворота каждого колеса это игровые
данные. Второй: цель Position-мотора теперь `m_curAngle`, а не `m_steerRadians`, как называл план.
В `m_curAngle` уже свёрнуты направление колеса, рейт-лимит и фактически достигнутый угол вместо
мгновенной команды — а для ТЕНИ совпасть с углом колеса эталона и есть вся задача.

### 100.4. Замер

Прямая, фаза газа, 3 повтора:

| | ratio | pos-div, м | angle, ° |
|---|---|---|---|
| `wm4_steer=0` (шаг 5) | 1.00 sd 0.01 | 2.52 sd 0.23 | 14.23 sd 1.97 |
| `wm4_steer=1`, упор 35° | 0.92 (1 прогон) | 24.80 | — |
| `wm4_steer=1`, упор π/4 | 0.94 sd 0.01 | 12.52 sd 1.40 | 9.93 sd 2.40 |

Слежение мотора в спокойных кадрах стало точным: `cmd=-0.086 meas=-0.087 err=-0.06 deg sat=0.01`,
`cmd=-0.141 meas=-0.156 err=-0.84`. Доля кадров в пределах 1°: 65/98 → 70/88 на прямой и 63/96 →
80/106 на руле в упор. Насыщение: 11/98 → 6/88 и 17/96 → 10/106.

Любопытная деталь, которую стоит назвать: угловая ошибка с включённым рулём **ниже** (9.93 против
14.23), а позиционная выше. Ориентацию руль улучшает, траекторию — пока нет.

### 100.5. Умолчание остаётся 0

Один прогон дал 0.99 / 4.43 и выглядел как проход. Три повтора дают 0.94 / 12.52 — тот прогон был
везением. Против проверенного бейслайна шага 5 это всё ещё впятеро худшая позиционная дивергенция
при sd 0.23 против 1.40, то есть далеко за шумом.

Находка большая и настоящая: она сняла выдуманную константу, убрала названную SPEC-ом неизвестную и
существенно улучшила шаг. Но она **не делает шаг 6 пройденным**, и умолчание меняется по замеру, а
не по значимости находки.

### 100.6. Что осталось

- `kApproxMaxSteerAngleRadians` (35°) **намеренно оставлена** для моды 2 и пути VehicleConstraint.
  Мода 2 — путь отката на каждом шаге этапа 1, и тихо менять поведение отката значило бы убрать то,
  ради чего откат существует. Перенос этих точек — отдельное изменение со своим замером.
- В худших кадрах колесо по-прежнему доходит до упора — теперь до правильного, ±0.785. Основной
  подозреваемый прежний и он же из §98.4: без прижимной силы §94 тень отрывается от земли, а колесо
  без нормальной нагрузки нечем удержать.
- `STEERING_INVERSE` в порту заголовка записано как `0xff`; `Str2WheelSteering` (0x1d0950) получает
  его через `neg al`, то есть это байтовое представление −1. Как именно оно попадает в int32-поле,
  которое `cvtsi2ss` читает целым dword-ом, здесь не выяснено — и не понадобилось, потому что
  `m_curAngle` уже несёт результат умножения.
