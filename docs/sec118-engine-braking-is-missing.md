
## §118. Механизм назван: у эталона есть торможение двигателем, у порта его нет

§117 закончился на «асимметрия измерена, причина не названа». Причина нашлась в бинарнике, и
отступил я от неё зря — из-за собственной ошибки разбора лога.

### 118.1. Что делает ODE

`ai::Vehicle::_KeepGearBox` (RVA 0x1e0e40, vehicle.cpp:6503-6640) в цикле по колёсам пишет два
параметра Hinge2. Разбор строк 6671-6674:

```
0x5e0e94: call ai::Sphere::GetRadius
0x5e0e99: fstp [esp+8]            ; радиус колеса
0x5e0e9d: fld  [esi+0x244]        ; m_averageWheelAVel
0x5e0ea5: fabs
0x5e0ea7: fmul [esp+8]
0x5e0eab: fstp [esp+0xc]          ; [esp+0xc] = |avgWheelAVel| * R  = скорость поверхности
...
0x5e11f6: xmm0 = gearTable[gear]
0x5e11ff: xmm0 *= [esi+0x1fc]     ; передаточное
0x5e1207: xmm0 *= [esp+0x14]      ; радиус
0x5e121e: xmm2 = xmm0 * [esp+0xc] ; <-- СКОРОСТЬ, а не газ
0x5e1224: xmm2 *= const
0x5e1238: xmm2 /= (count * X)
0x5e123c: [esp+0x18] = xmm2       ; -> dParamFMax2 (0x103)
```

**В капе силы нет множителя газа.** Он пропорционален текущей скорости поверхности колеса.

Целевая скорость (`dParamVel2`, 0x102) строится из `[esi+0x23c]`, делённого на то же передаточное —
а `[esi+0x23c]` накапливается на строках 6562-6566, то есть это обороты двигателя.

Отсюда поведение на накате: газ сброшен → обороты падают → заданная скорость колеса **ниже**
фактической → серво тормозит колесо, и кап при этом велик, потому что пропорционален скорости.
Это торможение двигателем, сильное на скорости и затухающее по мере остановки.

### 118.2. Что делает порт

`UpdateWheelSpinCommands`, ведомое колесо:

```cpp
target = gb.omegaTarget * sign(throttle);
limit  = std::fabs(throttle) * gb.perWheel;   // <-- множитель газа ЕСТЬ
```

При нулевом газе лимит — ноль, мотор не может ни разгонять, ни тормозить. Замерено на логе:
**98% кадров наката (176 из 179) имеют `cmdTq < 1 Н·м`**; оставшиеся три (298, 419, 574 Н·м) — кадры
перехода сразу после сброса газа.

В §117 я привёл «макс 720, среднее 43» и на этом основании отказался от объяснения. Это была моя
ошибка разбора: строки `§67: spin` печатаются в кадре **раньше** строки `§67: drivetrain`, а мой
парсер подставлял к ним газ **предыдущего** кадра. При правильной привязке среднее — 7.2 Н·м, и 98%
нулей. Отступать было не от чего.

### 118.3. Итог

```
эталон: FMax ∝ скорости, цель = обороты/передача   -> тормозит двигателем на накате
порт:   FMax ∝ газу                                -> на накате не тормозит ничем
```

Это и есть измеренная в §117 асимметрия: эталон гасит колёса с 46.4 до 0.02 рад/с за восемь секунд,
тень сохраняет 18%.

Значение выходит за рамки одного замера. Послегазовый хвост — худшая часть **каждого** прогона в
§103 и §108, и именно по нему принимались решения: умолчание `wm4_steer` (§108), оценка пакета
ассистов (§103), метрика `angle tail` в §110. Ни одно из тех чисел не отменяется — они измерены
верно, — но теперь известно, что заметная доля хвостовой дивергенции имеет **названную и
устранимую** причину, а не является неизбежным шумом схемы.

### 118.4. Отдельный механизм: автоторможение при отпускании газа (и `keep_throttle`)

Поправка от владельца проекта, и она по делу: в игре **есть** автоторможение на сбросе газа, и в
конфиге кракена есть параметр, который им управляет. Разбирать §118 без этого нельзя — иначе
читатель справедливо решит, что эталон встал именно из-за него.

`ai::Vehicle::_KeepThrottle` (RVA 0x1daae0, vehicle.cpp:6332-6498), строки 6355-6356:

```
0x5dabfa: movss [esi+0x22c], xmm0   ; m_throttle = 0
0x5dac02: movss xmm0, [0x9e597c]    ; <- адрес операнда, который кракен подменяет
0x5dac0a: movss [esi+0x230], xmm0   ; m_brake = <константа>
```

`entry.cpp:178` делает `RemapPtr(0x005DAC06, &keep_throttle.value)` — то есть **`keep_throttle` и
есть та величина тормоза**, которую автоторможение выставляет. Имя обманчиво: сейчас в ini стоит
`1.000000`, что означает полный тормоз при срабатывании; ноль означал бы «продолжать катиться»,
откуда имя и взялось.

Но весь блок закрыт флагом:

```
0x5dab16: cmp byte ptr [esi + 0x248], 0   ; m_bAutoBrake
0x5dab1d: je  0x5dac12                    ; не установлен -> блок пропускается целиком
```

А харнес в `KeepThrottleHook` ставит `vehicle->m_bAutoBrake = false` **каждый тик** скриптованного
прогона. Телеметрия это подтверждает независимо: за окно наката `autoBrake` = 0 на 100% кадров, а
`m_brake` держится 0.006, а не единицы из ini.

**Значит замер §117/§118 сделан при выключенном автоторможении, и измеренное торможение — не оно.**
Вывод остаётся, но теперь у него есть явно исключённая альтернатива, а не молчаливо
проигнорированная.

Два следствия, которые стоит держать в голове:

* `m_bAutoBrake` — механизм ИИ, привязанный к следованию по пути (`autobrakefix.cpp` работает от
  `vehicle->m_pPath`), так что у игроцкой машины он в норме не взведён. Для игрока торможение
  двигателем из §118.1 и есть основной механизм замедления на накате.
* Для машин ИИ картина другая, и переносить на них выводы §118 нельзя без отдельной проверки.

### 118.5. Чего я НЕ сделал

Не реализовал. Правка выглядит небольшой (кап, пропорциональный скорости, вместо газа), но она
меняет модель привода на закрытом этапе, и её нужно вводить рычагом с умолчанием «как было» и
мерить — ровно так, как вводились §101-103. Это следующий шаг, а не часть этой находки.

Не проверил и `[esp+0x10]` — множитель в знаменателе FMax, который в самой функции не пишется, то
есть входной параметр. На вывод это не влияет (множителя газа нет ни при каком его значении), но
точная формула капа без него не выписывается.
